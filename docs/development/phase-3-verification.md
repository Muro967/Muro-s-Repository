# 第三阶段验证说明

第三阶段提供灵感墙、五张有效灵感门槛、可编辑风格说明书、“不喜欢”规则，以及只使用本人现有衣物的规则复刻。OpenAI GPT 与通义千问是可选的服务端适配器；`AI_PROVIDER=none` 是默认且完整可用的模式。

有效灵感必须保存完整私有图片，并至少包含一个风格标签或颜色。前四张只显示“还差 N 张”，不显示虚构百分比。第五张后可整理风格说明书。人工修改说明书后，后续整理只产生待采纳建议；用户点击“采用建议”前不会覆盖人工版本。灵感字段一经用户修改会记为人工确认字段，异步 AI 也不会静默覆盖。

规则复刻的候选必须同时满足当前账号、`active` 状态和未删除。草稿、观察中、已处置、回收站及其他账号衣物在评分前排除；颜色、风格、版型、材质和正式程度规则是硬排除，自由文字规则只用于解释。结果必须以“上装 + 下装”或“连衣裙”为基础；鞋履缺失会如实显示。页面不提供购买推荐，也没有尚不可用的收藏、反馈或穿着按钮。

AI 请求只从服务端发出。浏览器只能读取 `available` 和显示标签，不能得到模型名、基础地址或 Key。服务端只向配置的精确 HTTPS 来源发送 Authorization，并禁用重定向；图片分析任务会去重、使用短租约并最多尝试两次。发送给复刻模型的是临时令牌和衣物公开描述，不包含个人备注、私有图片 URL、对象键或数据库用户编号。模型返回后仍会再次验证令牌、硬规则和组合完整性。

本地验收命令如下：

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

端到端测试使用隔离数据库与自动生成的纯色图片，不读取 `.data/pglite` 中的个人账号，也不访问真实 AI 服务。`inspiration-style-recreation.spec.ts` 会实际注册账号、添加上装/下装/鞋、上传 JPEG/PNG/WebP 五张灵感、编辑说明书、添加规则并完成规则复刻。生产部署仍需单独验证真实 HTTPS、PostgreSQL、私有对象存储、服务商额度与错误告警，以及 iPhone/Android 的相机、相册和安装体验。
