# 第二阶段验证说明

第二阶段提供可保存真实资料和私有原图的手动衣橱，包括多衣柜/分区、草稿、入库、分类/风格浏览、基础文字搜索、移动、软删除/恢复、闲置观察、处置和真实统计。基础安装步骤见[本地启动说明](local-setup.md)。所有命令在包含 `package.json` 的项目根目录运行，使用 Node.js 22 与 pnpm 11.25.0。

## 日期、闲置与观察

穿着日志尚未实现。`manualLastWornOn` 只是用户手动填写的最后穿着日，页面不会据此虚构穿着次数；未填写时以首次入库的 `addedOn` 为基准。草稿转入库时记录入库日，重复激活不会重写它。输入必须是真实的 `YYYY-MM-DD` 日期，不能晚于服务端允许的今天；观察中的穿着记录和闲置/处置/恢复使用保存的 IANA 时区。闲置设置默认 UTC，可由用户显式修改。

日数通过日期值进行 UTC 日历运算，避免夏令时一天不足或多于 24 小时造成偏移。入库不足 30 天的新衣不计闲置；满 30 天后仍须超过闲置阈值。默认闲置 90 天时，第 90 天不闲置，第 91 天才闲置。仅 `active` 与 `watching`、未删除且有入库日的衣物可计闲置。明确填写季节而不含当前季节的衣物被排除，未填写季节不会被排除，四季全选表示全年可用。没有手动季节覆盖时按用户当地月份使用北半球气象季节：3–5 月春、6–8 月夏、9–11 月秋、12–2 月冬；南半球或不同季节习惯应手动覆盖。

观察只能从当前闲置的在用衣物开始，默认 30 天。截止日等于开始日加当时的 `watchDays`，修改设置不会移动已有截止日。截止日当天仍未逾期，今天晚于截止日且仍计闲置时才显示逾期警告。观察中的衣物仍留在闲置分子中，逾期不会自动处置。取消观察保留穿着日期；在观察详情填写不早于观察开始日且不晚于服务端今天的手动穿着日期，会恢复 `active` 并清空观察日期。

## 统计与处置

可用数 `availableCount` 是未删除的 `active + watching` 数量；它包含宽限期和非当季衣物。闲置数 `idleCount` 是其中满足共享闲置规则的数量。已处置数 `disposedCount` 是未删除的 `disposed` 数量。草稿和回收站记录不参与这些计数。闲置率为 `idleCount / availableCount`；处置率为 `disposedCount / (disposedCount + idleCount)`；各自分母为零时结果为 0。接口提供原始比率，页面才显示百分数。已处置衣物不进入在用浏览、搜索或闲置候选。

处置支持二手卖出、送给朋友、捐赠、旧衣回收、改造和丢弃。售价与币种成对填写，售价按币种的小数位精确转换成整数最小单位（例如 CNY 180.00 保存为 18000）；不混加不同币种，不把未知售价当成实际收入。平台和收件人按方法选填，不相关字段被拒绝。收入只汇总已保存且未删除衣物的卖出记录，按币种分组。一次处置在事务中写记录并转为 `disposed`、清空观察日期；重试返回同一条记录，不重复累计收入。软删除处置衣物会从当前汇总排除其记录，但记录与原图仍保留。

## 私有图片、回收站与备份

原图支持 JPEG、PNG、WebP，最大 15 MB；服务器实际解码验证格式和完整性，限制像素/尺寸并拒绝动画，不只相信扩展名。相册和相机入口可提供即时本地预览；HEIC 须先转换。草稿可缺照片和位置，入库必须有名称、分类、完成上传的私有原图和属于本人的匹配衣柜/分区。原图通过登录态的同源接口读取，返回 `Cache-Control: private, no-store` 与 `X-Content-Type-Options: nosniff`；对象键、存储路径和云凭据不会作为图片地址交给浏览器。

移动只更新位置。软删除保留原状态、照片、观察与处置信息，删除后的前 30 个日历日可恢复（第 29 天允许，正好第 30 天拒绝）。当前没有自动永久清理或手动永久清除功能，过期记录与文件继续保留。图片替换也保留旧上传对象。不要把倒计时理解为已安排物理删除。备份必须停服务后将数据库目录、上传目录和 `.env.local` 一起备份到私有位置；只恢复数据库会缺图，详见本地说明。

文件和编辑内容只在当前页面的内存中保留，关闭前应保存。上传已有 ID 后的完成、绑定与保存支持重试；最初创建草稿/上传的 POST 如果响应丢失，没有请求幂等键可证明是否已经创建，可能留下未绑定的私有对象。对于结果不明的原图绑定，编辑器会锁定后续绑定并提供服务器照片核对；只有确认该次上传已绑定才能继续。通用请求状态/幂等协议和未绑定对象清理不在本阶段。

## 自动验证

首次运行先安装 Chromium；生产浏览器套件还需要终端可调用 OpenSSL（`openssl version`）。随后逐条执行，每条都应退出 0：

```bash
node --version
pnpm --version
pnpm exec playwright install chromium
pnpm test
pnpm typecheck
pnpm lint
pnpm build
node --test tests/build/upload-tracing.test.mjs
pnpm test:e2e
E2E_PRODUCTION=1 pnpm test:e2e
git diff --check
git status --short
```

Node 应为 `v22.x.x`，pnpm 应为 `11.25.0`，包括它们启动的子进程。部署追踪检查上传创建、上传内容、上传完成、原图绑定和私有图片读取五条路由，精确允许所需存储模块，拒绝参考素材、测试、私有数据、配置和其他源文件进入部署资产。

两个浏览器模式都执行邀请注册/首次设置/退出/登录、一次性邀请耗尽、全部受保护页面的匿名跳转、320/390/480 手机导航、真实 JPEG/PNG/WebP 上传与即时 blob 预览、草稿重开/入库/重载、图片字节一致、搜索/移动/回收/恢复、非空衣柜删除安置、闲置观察/逾期/取消/手动穿着/处置、收入幂等和规则保存。新入库的 30 天宽限期不能绕过，因此历史闲置旅程使用服务器启动前建立的独立旧衣夹具；测试没有生产时钟后门，也不会在服务运行时另开数据库写入。图片是生成的单色几何图，不含私人照片或参考图素材。

第二个独立账号通过直接 HTTP 请求对真实存在的他人衣柜、分区、衣物、资产、上传附件、观察和处置操作做探测，并与合法但不存在的 UUID 请求比较状态和 JSON，预期相同 404。附件探测使用真实 create → PUT → complete 获得的上传 ID，既检查他人衣物搭配自己完成上传，也检查自己草稿搭配他人上传；合法自有绑定作为正向对照。处置只有按衣物 ID 的命令，没有任意处置记录 ID 的公开读取/修改接口，因此验证该命令的 404 及他人处置记录在自身 dashboard 中不可见，不声称测过不存在的记录接口。

开发浏览器使用 `http://127.0.0.1:3109`；生产浏览器使用 `https://127.0.0.1:3109`，代理内部 `127.0.0.1:3110` 的真实 `next start`。测试拒绝复用服务，两个命令必须串行运行，生产模式需同时释放这两个端口。两个模式都覆盖隔离邀请和相同 reset。生产模式用 OpenSSL 在 `.data/e2e/tls/` 生成一天有效的自签证书，仅对测试浏览器放宽证书信任；应用的生产 HTTPS 与 Secure Cookie 保护保持启用，认证测试断言生产 Cookie 带 Secure。证书/私钥被 Git 忽略，下一次 reset 会清理。该本机 TLS 验证不代表真实公网证书和反向代理的部署验收。

生产套件额外执行 PWA 离线测试。PWA 只缓存通用离线页与公共图标，私有图片、API 和认证数据不进入 Service Worker 缓存。开发模式 Cookie 无 Secure，仅用于本地 HTTP。

reset 从脚本位置定位精确的 `.data/e2e/`，校验专用运行标记、密钥与数据库/上传目录，拒绝危险路径或符号链接，并在重置前校验全部邀请。真实 `.env.local` 的来源、数据库、存储和密钥被测试值覆盖。测试账号数据库、上传与生成图位于忽略的 `.data/e2e/`；邀请码原文只通过内存和进程环境传递，不另存明文文件。构建在 `.next-e2e/`。不要往这些目录放真实数据。测试结束由 Playwright 停止服务。

`output/playwright/task10/` 保存 development/production 两组 320、390、480 宽截图，覆盖衣橱、衣柜管理、编辑器、搜索、回收站、处置表单、闲置、规则和个人页。测试检查无水平文档溢出、可见操作目标至少 44×44、键盘焦点可见，采用 DetailShell 的衣柜管理、编辑器、搜索和回收站没有底部主 Tab；闲置、规则和个人页保留现有 AppShell 导航，处置弹窗隐藏后台导航。原有手机测试也检查全部主 Tab。截图和诊断均被忽略，不提交会话、数据库、上传原图或登录表单证据。
